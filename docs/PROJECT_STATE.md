## 4. Decided product requirements

Ниже перечислены решения, уже согласованные до начала кода нового репозитория.

### 4.1. Controller and equipment

**Decided:** центральный контроллер — Wiren Board.

**Decided:** фанкойлы подключены через обычные многоканальные релейные выходы.

**Decided:** вентиляционная машина подключена через Modbus.

**Decided:** автоматика фанкойлов и вентиляции будет реализовываться в WB Rules.

**Decided:** Web не должен напрямую дублировать эту автоматизацию.

### 4.2. Web technology

**Decided:** основной Web — статический HTML/CSS/JavaScript.

**Decided:** production Web должен работать без Internet.

**Decided:** допустимо подключать готовые модули/библиотеки только локально, если они реально нужны.

**Decided:** новый код не переносится из старого Web.

### 4.3. Primary user device

**Decided:** главный пользовательский терминал — iPad, установленный в конференц-зале.

**Decided:** интерфейс проектируется touch-first.

**Decided:** основная ориентация — landscape.

**Decided:** desktop browser используется для разработки и просмотра, но отдельная адаптация под большие экраны не требуется. Интерфейс сохраняет фиксированный планшетный canvas `1024×768` и не растягивается на широком мониторе.

### 4.4. UI direction

**Decided:** старый Web не копируется, но допускается использовать его дизайнерское направление: светлый фон, крупные карточки, чистое расположение и понятные active states.

**Decided:** управление температурной уставкой должно быть максимально близким по идее и пользовательскому ощущению к старому Blue Whale: значение над шкалой, фиксированный указатель вниз и горизонтальное цилиндрическое колесо с делениями, которое пользователь двигает пальцем влево/вправо.

**Current WEB-02 reference:** диапазон `18..28 °C`, шаг `1 °C` и чувствительность около `24 px / 1 °C` воспроизводятся как demo-поведение старого интерфейса. Эти параметры остаются доступными для явной последующей ревизии, если реальная климатическая логика потребует другой contract.

**Decided:** управление оборудованием должно быть крупным и удобным для пальца, без зависимости от hover.

### 4.5. Fan coils

**Decided:** должен существовать общий блок управления фанкойлами.

**Decided:** должен существовать отдельный экран/режим расположения 7 фанкойлов на плане помещения.

**Decided:** индивидуальное управление конкретным фанкойлом — только `ON/OFF`.

Точный финальный contract общих режимов/скоростей будет окончательно зафиксирован в соответствующем WEB/RULES шаге.

### 4.6. Ventilation

**Decided:** вентиляция отображается и управляется отдельно от фанкойлов.

Точный набор пользовательских режимов/скоростей будет окончательно утверждён в соответствующем шаге после UI-согласования и проверки фактического Modbus contract.

### 4.7. Airing / «Проветривание»

**Decided:** «Проветривание» является отдельным сценарием, а не просто ещё одной скоростью вентиляции.

Согласованная логика сценария:

```text
Start Airing
    -> сохранить предыдущее состояние
    -> включить fan coils на максимум
    -> включить ventilation на максимум
    -> установить минимальную температурную уставку
    -> запустить таймер
    -> после завершения вернуть сохранённое предыдущее состояние
```

**Decided:** пользователь с Web должен иметь возможность изменять время работы проветривания.

**Decided:** таймер и возврат состояния должны выполняться в WB Rules, а не зависеть от открытого Safari.

### 4.8. Lighting

**Decided:** целевое освещение — RGBW и управляется по DMX.

**Decided:** физический DMX/MQTT/Art-Net слой предоставляет существующий отдельный проект DMXWB.

**Decided:** Web Blue Whale должен поддерживать пространственный выбор одного светильника и группы/зоны на плане помещения.

**Decided:** детальное управление освещением должно включать user-friendly Power, цвет, яркость и управление белым/температурой в рамках возможностей DMXWB API.

**Decided:** Web должен поддерживать сцены DMXWB: применение, создание, переименование, перезапись и удаление.

### 4.9. DMX source selection

**Decided:** в Web должна быть явная кнопка/переключатель источника:

```text
WB MQTT
ART-NET
```

**Decided:** если выбран `ART-NET`, Blue Whale визуально показывает, что светом управляет ART-NET, и блокирует пользовательские органы MQTT-управления светом в **самом Web Blue Whale**.

**Decided:** при `ART-NET` остаётся доступной возможность переключить Source обратно на `WB MQTT`.

**Decided:** Blue Whale не добавляет server-side запрет MQTT-команд в DMXWB и не пытается контролировать другие MQTT-клиенты. Это не требуется.

## 5. Confirmed external DMXWB facts relevant to Blue Whale

По актуальной документации внешнего DMXWB подтверждён следующий integration model, который будет использован в спринте JS:

```text
Browser
  -> MQTT WebSocket /mqtt
  -> Mosquitto on Wiren Board
  -> DMXWB
  -> physical DMX512
```

Релевантные сущности DMXWB:

```text
/devices/dmxwb/controls/status
/devices/dmxwb/controls/source
/devices/dmxwb/controls/source/on

/devices/dmxwb_fixture_<id>/controls/<control>
/devices/dmxwb_fixture_<id>/controls/<control>/on

/devices/dmxwb_group_<id>/controls/<control>
/devices/dmxwb_group_<id>/controls/<control>/on

/dmxwb/config
/dmxwb/state
/dmxwb/status
/dmxwb/config/result

/dmxwb/scenes/create
/dmxwb/scenes/<id>/rename
/dmxwb/scenes/<id>/apply
/dmxwb/scenes/<id>/overwrite
/dmxwb/scenes/<id>/delete
```

Known user-facing Fixture/Group controls include:

```text
power
red
green
blue
color
brightness
temperature
reset
```

Known Source values:

```text
mqtt
artnet
```

Этот contract будет перечитан из актуального DMXWB перед реальной JS-интеграцией. Текущая документация Blue Whale не заменяет источник истины DMXWB.

## 8. Current WEB-02 iteration

`WEB-02 R4` продолжает температурную уставку с новым кодом, но намеренно повторяет характер исходного интерфейса:

- заголовок карточки изменён с `Климат` на `Уставка температуры`;
- отдельная дублирующая строка `Установка температуры` непосредственно над колесом удалена;
- временный placeholder `AUTO` из заголовка климатической карточки удалён, потому что для уставки температуры отдельный Auto-режим не был согласован;
- текущее значение по центру;
- фиксированный чёрный треугольный указатель;
- горизонтальное колесо/линейка с визуальной цилиндрической перспективой;
- крупные деления и подписи кратных пяти (`15`, `20`, `25`, ...), как в старом reference;
- промежуточные деления сделаны немного длиннее относительно R1, чтобы колесо визуально лучше совпадало с исходным reference;
- drag пальцем или мышью;
- направление drag соответствует старому UI: сдвиг шкалы вправо уменьшает уставку;
- после отпускания значение привязывается к целому градусу;
- клавиши стрелок/Home/End оставлены как вторичный desktop/accessibility способ управления;
- диапазон текущего demo-control `18..28 °C`;
- никакие MQTT-команды на этом этапе не отправляются.


Дополнительные корректировки R2/R3 по пользовательской проверке:

- область уставки температуры уменьшена по высоте;
- в R3 после удаления дублирующего заголовка область уставки дополнительно немного уплотнена, чтобы датчики получили ещё больше вертикального пространства;
- в R4 сохранена строка `Комфорт в помещении`, а внутренние элементы уставки распределены по высоте свободнее: увеличен отступ от заголовка до значения, добавлен промежуток перед указателем и колесом; сам блок почти полностью используется по высоте без возврата к прежнему чрезмерному размеру;
- освобождённое место отдано показаниям датчиков;
- показания температуры, влажности и CO₂ теперь занимают более заметную часть левой климатической карточки и расположены вертикально, ближе по пропорциям к исходному Blue Whale.

Старый HTML/CSS/JS не копируется: новый control реализован с нуля на Pointer Events и динамически создаваемых делениях. Старый проект используется только как reference внешнего вида и ощущения управления.

## 9. Current WEB-03 iteration

`WEB-03 R1` начинает отдельную доводку показаний помещения.

Текущий визуальный contract:

- на главном экране остаются три показателя: температура, влажность и CO₂;
- каждый показатель расположен отдельной горизонтальной строкой внутри нижней части левой карточки;
- сначала показывается понятная пиктограмма показателя, затем крупное числовое значение;
- подпись показателя остаётся вторичной и размещается под числом;
- иконки выполнены локальными inline SVG без внешних ресурсов;
- значения `22.4 °C`, `42 %`, `460 ppm` являются только demo-state текущего WEB-спринта;
- реальные factual values и поведение unavailable будут подключаться позже в спринте JS.

Цель R1 — проверить размер иконок, чисел и вертикальный баланс трёх показателей на iPad. Никакая MQTT-интеграция в WEB-03 не добавляется.

## 10. Revision policy

**Decided:** ранее принятые и даже уже реализованные решения можно пересматривать в последующих шагах, если появляется более удачный UX, новая фактическая информация или более простое решение. PASS фиксирует текущую рабочую базу, а не запрещает будущие улучшения. Любое изменение ранее подтверждённого поведения должно обсуждаться явно и не вноситься скрытно.
